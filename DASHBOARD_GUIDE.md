# IOSCAN Operator Dashboard

The dashboard provides a local operator interface for the scanner's acquisition and processing workflow.

## Install

Use the project's recommended Windows environment (Python 3.11):

```powershell
conda activate ios_scan
python -m pip install -e ".[dashboard,hardware]"
```

For automatic MeshSegNet inference, install PyTorch using the command appropriate for the workstation's CUDA driver, then install the segmentation extra:

```powershell
python -m pip install -e ".[seg]"
```

The two checkpoint archives should remain in the same models directory:

```text
C:\Users\arpit\MeshSegNet\models\MeshSegNet_Man_15_classes_72samples_lr1e-2_best.zip
C:\Users\arpit\MeshSegNet\models\MeshSegNet_Max_15_classes_72samples_lr1e-2_best.zip
```

The dashboard can use the model folder entered in its setup panel. Alternatively configure the environment variable:

```powershell
$env:IOSCAN_MESHSEGNET_MODELS = "C:\Users\arpit\MeshSegNet\models"
```

## Launch

From the project root (the folder containing `pyproject.toml`):

```powershell
python scripts/run_dashboard.py
```

Open `http://127.0.0.1:8787` in the workstation browser. The service binds to localhost by default.

## Scan workflow

1. Connect the USB camera and ESP32/BNO08x serial device.
2. Click **Refresh list** and select the physical Arducam / OV2311 by device name. Choose its DirectShow or Media Foundation entry as enumerated; do not select NVIDIA Broadcast, OBS, or another virtual camera. Set the ESP32 serial port (for example `COM3`).
3. Click **Check camera** to start the live preview. In **Camera ROI**, click the corners of the usable optical opening in order, then drag the round handles to refine the polygon. Use **Undo point** or **Clear** while editing. Check **Apply ROI to scan** and click **Save ROI** to enable it. The green polygon is retained; the outside area is shaded. Uncheck the option and save to process the full camera frame again.
4. The saved ROI is a normalized polygon in `configs/roi.json`; it is not hardcoded in source. At scan start, the dashboard copies it into that scan's `data/sessions/<session>/roi.json`, freezing the exact mask for reproducible reconstruction. It is applied after ON/OFF ambient subtraction and before laser-ridge extraction, so points outside the polygon are not triangulated. Older sessions without an ROI file are processed full-frame.
5. Select the jaw (`Lower · Man` or `Upper · Max`) and the reconstruction method.
6. Enter the measured camera-and-laser calibration JSON. Measured calibration is required for geometrically meaningful hardware scans; nominal defaults are only for software smoke tests.
7. Enter the MeshSegNet models folder and leave **Run MeshSegNet after reconstruction** enabled for the complete pipeline.
8. Click **Start scan workflow**. The live camera feed and ROI-filtered fused 3D point-cloud preview update while recording. Stopping capture saves the session and begins full reconstruction, followed by segmentation when enabled.
9. Open the reconstructed mesh, colour-labelled result, teeth-only model or individual tooth-class PLY files from **Export files**.

The **Run / retry MeshSegNet** button can rerun segmentation on the already reconstructed mesh without repeating acquisition or reconstruction. It uses the current jaw selection and model folder.

## Data locations

The dashboard creates a timestamped session directory under `data/sessions/` and writes reconstruction/segmentation outputs to the corresponding directory under `data/results/`. The session metadata stores the jaw selection and dashboard processing parameters.

## Hardware and accuracy notes

- The camera feed and point-cloud preview are real hardware data; the dashboard does not substitute synthetic frames when no camera is connected.
- The live viewport is an accumulating point-cloud preview. The final triangle surface is generated by the full reconstruction stage after capture.
- The current reconstruction's `imu_hybrid` pose mode requires a valid ESP32 quaternion stream. It estimates translation using the configured nominal scan speed; a gyroscope alone does not measure translation. An encoder or another reliable translation source is needed for metrologically accurate motion.
- If no calibration JSON is supplied, the capture logger uses nominal example camera intrinsics and laser-plane geometry. The dashboard/pipeline warn about nominal calibration; such output should not be used for measurement.
- The idle camera preview uses driver auto exposure for visibility. Synchronized scan capture switches to the configured fixed exposure (default -7) for consistent alternating laser-OFF/laser-ON acquisition. A black idle preview should be checked for lens obstruction and adequate scene illumination before scanning.
- MeshSegNet predicts labels only on the reconstructed surfaces. Missing tooth walls or missing arch coverage cannot be generated by segmentation.
- The browser's interactive 3D viewer loads Three.js ES modules from jsDelivr, so the workstation browser needs internet access for the 3D viewport. Camera acquisition, reconstruction, model inference and file storage run locally.
- This is an engineering development interface, not a validated clinical or diagnostic workstation. Keep the service bound to localhost unless authentication and network access controls are added.

## ESP32 firmware reference and synchronization

The firmware sketch and its notes are included in `firmware/esp32_scanner/`. The updated sketch emits
`@timestamp_us,laser_on,qw,qx,qy,qz,frame_sequence*CRC16` at 115200 baud (CRC-16/CCITT-FALSE). The Python capture logger accepts
that format and the previous six-field format, consumes one queued ESP32 event per camera image,
extends the 32-bit MCU `micros()` counter across wrap, and fails if sequence gaps or queue overrun
are detected. The first exposure is laser-OFF, followed by alternating OFF/ON exposures.

The sketch deliberately does not emit synthetic 50 Hz events if camera STROBE is absent. It forces
the laser gate low and reports a warning; the dashboard capture then times out instead of building a
scan from unsynchronized frames. If BNO086 initialization fails or its orientation samples become
stale, valid scan packets are withheld rather than sending an identity quaternion.

**Hardware verification is still required.** OpenCV's current UVC capture path does not expose a
hardware frame ID/timestamp, so one-to-one serial/image order must be confirmed on the actual camera
and Windows driver. Confirm 1600x1200 capture, frame rate, exposure, STROBE polarity, no packet gaps,
and laser OFF/ON image alternation before scanning a full arch. See the project README and firmware
README for the remaining translation/extrinsic calibration limitations.
